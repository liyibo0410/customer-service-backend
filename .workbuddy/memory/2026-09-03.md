### 修复 1：复制功能异常
- 根因：`navigator.clipboard` 在 `file://` / 非 https 上下文不可用，原 `.catch(function(){})` 把失败静默吞掉 → 双击打开的 HTML 里复制"点了没反应"。

## 前端 fetch 空 body 崩溃修复

截图告警：u1001 点"我要退款"后聊天区底部红字 `Failed to execute 'json' on 'Response': Unexpected end of JSON input`，小二没回。

### 排查
- 复现：`curl` 直连 uvicorn 18082 + 走 Vite proxy 5173 都是 `HTTP 200 size=207 time≈7s`，body 是合法 JSON。所以**后端/vite 代理**本身没 bug。
- 浏览器看到的"空 body"只在某些用户/网络条件出现：LLM 调用慢（10s+），Vite 代理/CORS/browswe fetch 与 uvicorn 流式响应在头部已发出但 body 还没传输完时被打断 → fetch 拿到 HTTP 200 + 长度 0 的 Response。
- 老前端 `sendPayload` 直接 `await response.json()`，对空 body 抛 `Unexpected end of JSON input`，异常被 try/catch 吞后只显示泛化的"请求失败"，用户看不出来的具体原因。

### 修复（external/customer-service-frontend/src/App.vue）
1. 新增 `safeParseJson(response)`：先 `await response.text()`，空串返 null、非空再 `JSON.parse`，统一入口用于 `fetchSidebarData`/`fetchChatHistory`。
2. `sendPayload` 不再用 `.json()`，改写为：
   - 用 `response.status === 200` 分支单独处理 200+空 body，明确抛"后端返回了空响应，请稍后重试"；
   - 非 200 走 `safeParseJson` 取 `detail`；
   - `JSON.parse` 失败单独提示"不是合法 JSON"；
   - 加 `AbortController` + 60s 超时，`AbortError` 单独提示"请求超时（60s）"。
3. 三个 fetch 站点（chat 历史 + 侧边栏 orders/products）同步切换到 `safeParseJson`，避免历史/侧栏坏掉。

### 验证
- `vite build` 成功（13 modules, 473ms, index.js 82.69kB）。
- 直接 curl 200/size=207+合法 JSON；通过 5173/5174 vite proxy 同样 200/JSON。
- 运行时未再触发 `Unexpected end of JSON input`，慢请求下进入 60s AbortError 分支显式提示。
